# qPCR Rhythm Guard 中文使用说明

这是一个面向实验室研究者的 qPCR 质控与固定周期节律分析原型。首版将原始 Ct、技术重复、生物学样本、归一化结果和模型结果放在同一条可追溯流程里，帮助研究者找到需要核对的记录。

当前版本为 0.1.0，已包含可运行代码和合成示例，尚未经过外部用户验证。[项目仓库](https://github.com/Gaikunxingle/qpcr-rhythm-guard)由 [Gaikunxingle](https://github.com/Gaikunxingle) 维护。软件包索引中的名称尚未预留，请从本仓库安装。

## 先看示例

交付包中的 `demo/report.html` 可直接在浏览器打开。所有示例值均为人工生成，其中故意保留了未检出记录。示例的数值与模型结果不代表真实实验。

安装 Python 3.10 或以上版本后，在项目文件夹运行：

```sh
python -m pip install .
python -m qpcr_rhythm_guard examples/synthetic.csv --config examples/config.json --out results/my_demo
```

打开 `results/my_demo/report.html` 查看结果。软件在本机处理数据，不需要 OpenAI API 密钥或付费订阅。依赖包安装时需要访问软件包来源，分析本身不上传数据。

## 首版能做什么

1. 检查重复记录、样本标识冲突、非法数值、内参缺失和技术重复离散情况。
2. 在每个样本内先合并技术重复，再计算 ΔCt、log2RQ 和 RQ。
3. 进行预先固定周期的 Cosinor 拟合，默认周期为 24 小时。
4. 当明确声明独立样本设计、且通过软件门槛时，计算零振幅 F 检验并做 BH 校正。
5. 导出可读报告、逐样本数据、模型表、质控表、矢量图和运行校验记录。

首版只接受项目规定的长表 CSV。仪器 `.xls`、`.eds`、原始扩增曲线和原生 Prism 项目尚未接入；也没有图形化数据导入界面。当前 HTML 是结果报告。

## 准备真实数据

按 [输入规范](docs/INPUT.md) 将数据整理为 UTF-8 CSV。使用真实的生物学单位标识，不能把每个技术孔都编号为独立样本。保留 `Undetermined`，不要补为 0 或 Ct=40。

复制 `examples/config.json`，设置内参、校准组与校准时间。`design` 默认 `unknown`，仅作描述性拟合。只有明确属于独立取样设计时才设置为 `independent`；同一动物、同一独立培养体系的连续取样属于相关观测，首版不对其进行推断。

阈值 `technical_sd_limit=0.5` 是可调整的软件提示阈值，不是适用于所有实验的标准。应依据实验方案预先确定，不能为了改变显著性反复调整。

## 如何看结果

- `normalized.csv`：每个样本和目标基因的归一化结果及缺失原因。
- `fits.csv`：有效样本量、MESOR、振幅、峰相位、检验状态和 P/q 值。
- `qc.csv`：需核对的问题。提示不等于自动删除数据。
- `results.json`：保留标识和明细的机器可读结果。
- `figure_*.svg/png`：观测 RQ 和 log2RQ 拟合。曲线只画到最后一个有效观测时间。
- `manifest.json`：输入与配置校验值、软件版本及输出文件校验值。

`NA` 表示未计算或不可检验，不能解释成“没有变化”。峰相位相对于输入的时间 0，不能自动称为 ZT。某一组显著、另一组不显著，也不能推出两组之间存在差异。

单内参稳定性、扩增效率和模型残差假设都需要另外验证。当前流程不认证 MIQE 合规，也不能仅凭固定 24 小时拟合证明内源性昼夜节律。具体模型和门槛见 [方法说明](docs/METHODS.md)。

## 下一步怎么发展

先选择一份你有权使用的真实实验数据，在本机核对与手工计算是否一致；公开仓库仍使用合成示例。随后请少量研究者按说明独立运行，记录真实遇到的问题，再根据反馈决定优先增加仪器导入、重复测量支持或界面。

遇到问题时，请在 [Issues](https://github.com/Gaikunxingle/qpcr-rhythm-guard/issues) 中提供可公开的最小示例、配置、软件版本和预期结果。
